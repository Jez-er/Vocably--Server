# Тести

```bash
make test     # unit + інтеграційні
make check    # те саме + перевірка форматування (== ./gradlew build)
```

Інтеграційні тести піднімають реальний Postgres через Testcontainers — потрібен запущений
Docker.

## Що покрито

| Клас | Тестів | Про що |
| --- | --- | --- |
| `WordOwnershipIntegrationTest` | 7 | owner-scoping слів, включно з записом у чужий словник |
| `DictionaryOwnershipIntegrationTest` | 8 | owner-scoping словників, конфлікт мови, нормалізація коду |
| `LanguageAccessControlTest` | 4 | 403 для `USER`, 201 для `ADMIN`, 401 без токена, читання відкрите |
| `AuthControllerTest` | 10 | статуси й тіло помилок, на які гілкується клієнт |
| `SecurityConfigTest` | 6 | правила доступу, CORS preflight, форма 401 |
| `JwtAuthenticationFilterTest` | 3 | автентифікація з bearer-токена |

Покриття свідомо зосереджене на owner-scoping: це центральний інваріант безпеки API, і
зламати його тихо найлегше — достатньо впустити фільтр в одному запиті з кількох.

## Чому проти справжнього Postgres, а не in-memory

Те, що тут варто перевіряти, існує лише там: міграції Flyway, колонки `TEXT[]`,
`gen_random_uuid()` і унікальні констрейнти, на які спирається код. `ddl-auto` лишається
`validate`, тож розбіжність між entity й міграцією валить прогін замість того, щоб бути
прикритою згенерованим DDL.

## Один контейнер на весь прогін

`PostgresIntegrationTest` стартує контейнер у статичному ініціалізаторі й навмисно не
зупиняє — його прибирає shutdown hook Testcontainers. Контейнер на клас платив би за старт
у кожному тестовому класі.

## Чому тести не `@Transactional`

Відкат тестової транзакції приховав би унікальні констрейнти й каскади, які ці рядки
насправді мусять задовольняти. До того ж очікуваний виняток, що виходить із сервісного
методу, помітив би спільну транзакцію `rollback-only` посеред тесту — і наступне читання в
тому ж тесті впало б із причини, що не має стосунку до перевірки.

Замість відкоту — унікальні email на кожен тест (`name-{UUID}@example.com`).

## Redis у тестах

Вимкнений: автоконфігурація виключена, `revocation-enabled: false`. Другий контейнер
сповільнював би кожен прогін, а нічого з покритого refresh-токенів не торкається — тоді
Redis-backed whitelist підміняється no-op реалізацією.
